## Scenario A — "Research the top 5 competitors of my company and tell me what content opportunities we are missing."

1. **User request** — Command Center input; brand "Acme Billing" selected. `POST /api/v1/ai/runs {message, brand_id, mode:"task"}` → `ai_runs(status=queued)`, `ai_messages(role=user)`, job `jobs.ai.run` enqueued (same txn) → `202 {run_id}`; UI subscribes SSE topic `runs`.
2. **Intent detection** — worker: ContextBuilder loads BrandContext (compact), preferences, conversation summary, top-8 memories. IntentRouter (cheap model, structured): `{intent:"research_competitors", entities:{limit:5}, secondary:["find_gaps"], clarification_needed:false}`. `ai_runs.intent` saved; status `planning`; `AI_RUN_STARTED`.
3. **Agent planning** — Planner (powerful) seeded with template `research_competitors+gaps` emits the plan (doc 05 §2.4): t1 `competitor_intel.resolve_competitors(5)` → t2 `research.research` (fan-out per competitor website, depth standard, recency 90d) ‖ t3 `social_listening.collect_public_posts` (fan-out) → t4 `competitor_intel.analyze` (fan-in) → t5 `competitor_intel.find_gaps` → t6 `report.compose(competitor_opportunities)`. PlanValidator passes (est. cost $0.90 < budget $1.50). `ai_tasks` rows created; status `running`. SSE: "Planning… ✓ 6 steps".
4. **Competitor lookup** — t1: tool `competitors.list(brand_id)` returns 3 stored competitors; agent calls `web.search("Acme Billing competitors medical billing services", kind=web)` to propose 2 more; outputs 5 `{competitor_id|candidate, website, handles}`; candidates are created as `competitors` rows with `status=active` and `profiles` classified by availability (website B; Instagram A if the brand's IG account via Facebook Login is connected; LinkedIn posts E; YouTube A if a channel is found). `AI_RUN_STEP_COMPLETED(t1)`; SSE "Checking competitors ✓".
5. **Research** — t2.1…t2.5 in parallel (max_parallel 3): each `research.research(query=<competitor> site:<domain> + news "<competitor>")` → query planning → search fan-out (Tavily + news) → fetch via SafeFetcher (robots respected) → extract (trafilatura) → hash/dedupe → enrich (summary, keywords, claims) → score → `research_sources` (upsert by canonical URL; reuse if < 24 h), `research_documents`, `research_chunks` (+embeddings job) → `research_runs(result)`; `RESEARCH_COMPLETED`. SSE per sub-step "Researching web (3/5) ✓".
6. **Source collection** — t3.x: `social.profile(instagram, handle)` via Business Discovery (followers, media_count, last 25 media with like/comment counts; `view_count` for Reels) → `competitor_profiles` + `competitor_posts` (availability=official_api); `social.profile(youtube, channel)` → channel statistics + `videos.batchGetStats` for last 20 uploads (30-day retention tag); LinkedIn: `organizations` + `networkSizes` follower count only; profiles for TikTok/Pinterest recorded as `not_collected` with reason. `COMPETITOR_UPDATED`. SSE "Collecting public posts ✓ (2 platforms unavailable — see details)".
7. **Data normalization** — deterministic in the collectors: posts mapped to `competitor_posts` schema, hashtags/mentions extracted, formats inferred, engagement counts stored or `NULL`; `competitor_snapshots` written (frequency 7/30d, format mix, hours); embeddings queued.
8. **Competitor analysis** — t4: `competitor_intel.analyze` per competitor: tool `stats.describe(profile_id)` (cadence, mix, hours, hashtag frequency) + `research.read_source` for top sources + `competitors.list_posts` (wrapped as untrusted) → LLM labels pillars, hooks, tone, offers, campaigns, website changes, strengths/weaknesses with post/source ids → `competitor_posts.analysis`, `competitor_reports(kind=single)` draft content. SSE "Analyzing competitors ✓".
9. **Gap detection** — t5: tool `competitors.topic_clusters(brand_id, competitor_ids)` (embeddings of our last 90 days content + competitor posts/pages → clustering → coverage table) → LLM names gaps with evidence ids and `brand_fit` (similarity to pillars; forbidden topics excluded) → `GapAnalysis{gaps[], recommendations[]}`.
10. **AI reasoning** — agents produce `reasoning_summary` bullets (non-chain-of-thought): "5 competitors analyzed; 2 platforms not collectible by policy; 4 gaps found with ≥ 2 competitors covering each; strongest: 'denial-management explainers' (3 competitors, high news velocity, no Acme coverage)". CitationTracker verifies every source id exists.
11. **Report generation** — t6: `report.compose(kind=competitor_opportunities)` → `reports.get_data` pack (analyses, gaps, snapshots, sources) → markdown sections + charts spec → `reports` row + rendered HTML in MinIO → `REPORT_GENERATED`.
12. **UI result** — `AI_RUN_COMPLETED`; `ai_runs.result = {deliverables:{report_id, gaps[]}, sources[], reasoning_summary, actions:[]}`; cost $0.74, tokens 118k. Command Center shows: steps ✓ with durations; Sources (ranked, credibility); Reasoning summary; Generated: "Competitor Opportunities report" (open) + 4 gap cards (each: evidence, competitors, brand fit, "Create ideas" button); Actions: none pending; "Not collected" notice for TikTok/Pinterest/LinkedIn posts.
13. **Save research** — all artifacts already persisted (`research_runs`, `research_sources`, `competitor_*`, `reports`); the run ledger (`ai_tasks`, `ai_tool_calls`, `ai_calls`) is complete; usage recorded in `usage_ledger`.
14. **Update brand memory** — MemoryService writes `memories(kind=note, text="Top gaps vs competitors (Oct 2026): …", importance 0.8, source_ref{run_id, report_id})` and a conversation summary; `brand_settings.strategy.evidence_ids` gains the report id (pending user acceptance).

### "Create 10 posts from those opportunities."
1. `POST /ai/runs {message, conversation_id}` → IntentRouter `{intent:"write_post", entities:{count:10, from:"last_result.gaps"}}` (conversation memory resolves "those").
2. Planner: t1 `ideation.generate(count=10, from={gaps, report})` → t2 `writer.write × 10` (fan-out, platform per brand strategy: 5 LinkedIn, 3 Instagram carousel captions, 2 X threads) → t3 `critic.critique × 10` → t4 `fact_check.check × 10` (claims from research) → t5 `visual.concept × 10` (concept + alt text only; image generation is SPEND and not requested). Estimated $2.10 > `confirm_above_usd` $2 → run status `awaiting_approval(kind=spend)`; UI asks "Approve ~$2.10?" → user approves → resume.
3. Ideation: dedupes against last 500 ideas (embeddings) → `content_ideas × 10 (status=promoted)`.
4. Writer per idea: BrandContext full, `research.read_source` for evidence, `platform.rules`, `hashtags.suggest` → `content.create_draft` → `content_items(status=ai_generated, ai_generated=true, generation_metadata)`, `content_versions(v1, author=agent:writer)`, `content_sources` (claim-level), `content_variants` (first platform variant).
5. Critic: scores + issues → `content_items.critique`; risk level set (two items `medium` due to regulatory claims).
6. Fact-check: claims → verdicts; one `unverifiable` claim in a regulated domain → that item `risk_level=high`, flagged "needs admin approval".
7. Visual: `visual_concept` + `alt_text` stored in `body`.
8. `CONTENT_CREATED × 10`, `AI_RUN_COMPLETED`. UI: 10 content cards with scores/risk, "Open in Studio", "Request approval" (bulk). User bulk-requests approval → `approvals × 10`, `APPROVAL_REQUESTED`, notifications to approvers.

### "Schedule the best 5."
1. IntentRouter `{intent:"schedule", entities:{count:5, selection:"best"}}`.
2. Planner: t1 `strategy.select_opportunities(candidates=10 items, n=5, criteria=critic.quality+brand_fit+pillar balance)` → t2 `publishing.propose_schedule(variant_ids×5, strategy=best_time)` (APPROVAL tool).
3. t1 selects 5 (explains ranking). t2 calls `scheduling.best_times` (needs ≥ 3 posts per cell; brand has 40 published posts → data-based slots) → builds a proposed action list: `[{variant, account, at}]×5` → `approvals(kind=ai_action, payload)`; run `awaiting_approval`; `AI_RUN_AWAITING_APPROVAL`; UI Actions panel: "Schedule 5 posts" with the table and Approve/Reject.
4. Approver clicks Approve → `POST /approvals/{id}/approve` → ApprovalGate executes `SchedulingService.schedule()` per item: content status must be `approved` — 3 are approved, 2 are still `needs_review` → gate schedules 3 and returns a partial result `{scheduled:3, blocked:2 (needs approval)}`; agent reports accordingly. `scheduled_posts × 3 (status=scheduled)`, `POST_SCHEDULED`, calendar updates via SSE.
5. When the remaining 2 are approved later, the user clicks "Schedule" in the Approvals inbox (or re-asks the AI).
6. At `scheduled_at`: scheduler → `queued` + job → worker → adapter (LinkedIn: `initializeUpload` image → PUT → `POST /rest/posts`) → `published_posts` → `PUBLISH_SUCCESS` → metric pulls scheduled.

### "Analyze performance after 30 days."
1. IntentRouter `{intent:"analyze_performance", entities:{period:"30d"}}`.
2. Planner: t1 `performance_analyst.analyze(period=30d, dimensions=[pillar, format, platform, hour, topic])` → t2 `report.compose(weekly_performance variant=30d)`.
3. Precondition check: AnalyticsSync has pulled `post_metrics` on the decaying cadence (1h…30d) for the posts; account metrics daily.
4. t1 tools: `stats.compare_groups(engagement_rate, by=format)` → "carousel n=6 vs image n=9, +42%, CI wide → early signal"; `by=pillar` → "educational 2.1×, n=11"; `stats.time_of_day` → "10–12 best, n=14"; `competitors.delta(30d)` → "Competitor X frequency 3→7/wk". LLM writes `insights` (4) and `recommendations` (3: more carousels on IG, shift 10% mix to educational, schedule LinkedIn 10–12).
5. `AI_ANALYSIS_COMPLETED`, `RECOMMENDATION_CREATED` → notification → Dashboard "What to do next" card; memory `kind=performance` written.
6. User accepts "shift mix" → `strategy.recommend_mix` applies the deterministic adjust rule → new `brand_settings.strategy.version`; accepts "more carousels" → `ideation.generate(from=insight)` → 10 carousel ideas in the planner. The loop closes.

## Scenario B — "Every Monday at 9 AM, research my industry, find important news, analyze competitors, create 10 content ideas, and put them in my content planner."

**Setup (one-time):** Command Center → IntentRouter `configure_automation` → the orchestrator proposes a workflow from the template "Weekly industry research → ideas" with parameters `{cron:"0 9 * * 1", tz: brand.timezone, idea_count:10}` → Actions panel "Create automation" → user approves → `automation_workflows(status=active)`, nodes: `trigger.cron` → `research` (industry news, 7d) → `action(competitors.sync all)` → `ai_agent(trend.detect)` → `ai_agent(strategy.recommend_mix?)` (optional) → `generate(ideas, 10, from=research+trends+competitor deltas)` → `action(ideas.add_to_planner)` → `notification`. `next_run_at` computed.

**Each Monday 09:00 (brand tz):**
1. **Trigger** — scheduler `dispatch_automation_cron()` → `automation_runs(status=running, trigger_type=cron)` → `AUTOMATION_TRIGGERED` → job `jobs.automation.execute`.
2. **Automation engine** — step `research`: `ResearchService.run(query=brand.industry + " news", scope=[news,rss,web], recency=7d)` → `AIService.create_run(mode=automation, agent=research)` → run id stored on the step; engine yields; resumed on `AI_RUN_COMPLETED`.
3. **Research** — pipeline as in Scenario A step 5; sources flagged by the injection classifier are excluded automatically (automation policy).
4. **Competitor analysis** — step `action(competitors.sync)`: `jobs.competitors.sync_profile` for every active profile (budget-aware: X reads counted; YouTube quota checked) → new `competitor_snapshots` → `COMPETITOR_SNAPSHOT_TAKEN`; deltas vs last week computed deterministically.
5. **Trend analysis** — step `ai_agent(trend.detect)`: `trends.signals` (term velocity over research sources + competitor posts + keywords, 14-day window) → LLM labels clusters → `trends` upserted (`TREND_DETECTED` for new ones ≥ threshold).
6. **Content strategy** — step (optional) `ai_agent(strategy.recommend_mix)` reads last week's insights; outputs pillar emphasis for this week (not persisted as a new strategy version unless accepted; stored in run context).
7. **Content ideas** — step `generate(ideas)`: `ideation.generate(count=10, from={research_run_id, trend_ids, competitor_deltas, mix_hint})` with dedupe → `content_ideas(status=new, evidence{…})`.
8. **Database** — step `action(ideas.add_to_planner)`: ideas tagged `planner_week=2026-W42`, campaign optional; `CONTENT_CREATED`-style event `IDEAS_ADDED` (payload lists ids).
9. **Notification** — step `notification`: in-app + email "10 new ideas for week 42 (3 from trends, 4 from competitor gaps, 3 from news)" with a link to Ideas filtered by week; `AUTOMATION_COMPLETED`; run cost recorded (`usage_ledger`); run visible in Automations → Runs with per-step logs and links to the AI runs.

Failure handling: if research fails (search providers down), `on_error=notify` sends "Weekly research skipped: search unavailable" and the run is marked failed with retry at 10:00; if the budget is exceeded, the run pauses with `BUDGET_EXCEEDED` and resumes next period.

## Scenario C — "Create one LinkedIn post about the latest healthcare billing news and automatically create Instagram, Facebook, X and TikTok versions."

1. **Research** — IntentRouter `{intent:["research_topic","write_post","repurpose"], entities:{topic:"healthcare billing news", platform:"linkedin", targets:[instagram,facebook,x,tiktok]}}`. Planner: t1 `research.research("healthcare billing news", scope=[news,rss], recency=7d, depth=quick)` → t2 `writer.write(platform=linkedin, content_type=industry_news, sources=t1.top5)` → t3 `fact_check.check(t2)` → t4 `repurposer.adapt × 4` → t5 `visual.concept + generate_image` (SPEND; under threshold) → t6 `critic.critique × 5` → deliverables. Research returns 12 sources, 5 selected (credibility ≥ 0.6, published ≤ 7 d).
2. **Fact checking** — claims extracted from the brief *and* the draft: "CMS finalized rule X on date Y" → `supported` (2 sources, quotes stored); "denials rose 20%" → `unverifiable` → draft revised by writer (`rewrite` with instruction "remove or attribute the 20% figure") → re-check → `supported` with attribution.
3. **Master content** — `content_items(master_format=text, content_type=industry_news, status=ai_generated)` with hook/body/CTA/hashtags/keywords/visual_concept/alt_text/sources; LinkedIn variant created (`content_variants`), validated by `platform.rules` (≤ 3,000 chars, ≤ 5 hashtags per brand policy, link in body).
4. **Platform adaptation** — repurposer fan-out: Instagram caption (≤ 2,200 chars, hashtags block, "link in bio", carousel slide text ×5 proposed), Facebook post (conversational, link preview), X thread (5 posts ≤ 280 chars; link only in the last post — and the validator warns "X posts containing a URL cost $0.20"), TikTok script (30 s: hook, 3 beats, on-screen text, CTA; note: the connected TikTok account is unaudited → `inbox_upload` mode; the user will finalize in the TikTok app). Each variant records `changes_made[]`.
5. **Visual generation** — `visual.concept` → brand-styled image prompt (navy/teal, documentary style, no faces) → `media.generate_image` (ImageProvider primary; cost $0.04) → MinIO → `media_assets(ai_generated=true)` → renditions: IG 4:5 JPEG, FB 1.91:1, X 16:9, LinkedIn 1.91:1 → `content_assets` per variant with alt text; TikTok cover frame suggestion only. `MEDIA_GENERATED`.
6. **Critic** — per variant: scores, platform-fit (IG: hashtags count ok; X: segment 3 is 284 chars → issue), policy flags (none), risk `medium` (regulatory topic) → `needs_review`. Writer auto-fixes the X segment length on the critic's suggestion (one bounded revision loop), re-validated.
7. **Approval** — `APPROVAL_REQUESTED` (one approval covering master + 5 variants); Approvals inbox shows per-platform previews, claims with evidence, sources, scores, generation metadata; approver approves master + 4 variants, requests changes on TikTok script ("shorter CTA") → TikTok variant back to `draft` with comment; writer/user edit → re-approve.
8. **Scheduling** — Actions panel proposes best-time slots per account (LinkedIn Tue 10:30, IG Tue 12:00, FB Tue 13:00, X Tue 09:15 thread, TikTok Wed 18:00) → approver approves → `scheduled_posts × 5` (TikTok one flagged `inbox_upload`: "will land in your TikTok inbox; finalize in the app").
9. **Publishing** — at each time: scheduler → worker → adapters: LinkedIn (`initializeUpload` image → `POST /rest/posts`), Instagram (`POST /{ig}/media` with public image URL via MediaPublicURLService → poll `FINISHED` → `media_publish`), Facebook (`POST /{page}/photos` with caption), X (media v2 upload → `POST /2/tweets` ×5 as reply chain; segment ids recorded; if segment 4 times out → reconcile via `users/:id/tweets` → continue), TikTok (`post/publish/inbox/video/init` with FILE_UPLOAD chunks → `publish_id` → status polled → "SEND_TO_USER_INBOX") → `published_posts`, `PUBLISH_SUCCESS` ×5 → notifications → metric pulls scheduled; the Dashboard shows the five posts live with links.
