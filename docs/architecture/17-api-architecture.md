# 17 — API Architecture

REST over HTTPS, JSON, versioned at `/api/v1`. OpenAPI generated by FastAPI; the frontend consumes a generated TypeScript client. The full route catalog is in doc 00 §14; this document specifies conventions and the important endpoints in detail.

## 17.1 Conventions

- **Auth:** `Authorization: Bearer <access JWT>` (15 min) or the `botwok_access` cookie set by the Next proxy; refresh via `POST /auth/refresh` using the `botwok_refresh` httpOnly cookie. API keys (`X-API-Key`) for automation/webhooks with scoped permissions.
- **Workspace scoping:** every non-auth route requires `X-Workspace-Id` (or `/workspaces/{ws}` in path). The dependency `current_member()` loads the membership and role; it sets `app.workspace_id` on the DB session for RLS.
- **Authorization:** declarative per route: `require_role("editor")`; object-level checks in services (e.g. only approvers can approve; editors can schedule only `approved` variants).
- **Pagination:** cursor-based: `?limit=50&cursor=…` → `{items, next_cursor}`; sorting `?sort=-created_at`.
- **Filtering:** query params; multi-value as repeated params (`platform=x&platform=linkedin`).
- **Errors:** RFC 9457 Problem Details: `{type, title, status, detail, instance, errors[]}` with stable `type` slugs (`validation_error`, `not_found`, `conflict`, `forbidden`, `rate_limited`, `budget_exceeded`, `platform_error`, `token_expired`).
- **Idempotency:** mutating POSTs accept `Idempotency-Key`; the server stores `(workspace, key) → response` for 24 h in Redis.
- **Long operations:** return `202 Accepted` with `{job_id|run_id, status_url}`; progress via SSE.
- **Rate limits:** per user 600 req/min, per API key 300 req/min, per IP for auth routes 20/min; `429` with `Retry-After`.
- **Versioning:** breaking changes → `/api/v2`; additive changes in place. Platform adapters pin their own external API versions.

## 17.2 Key endpoints

### Auth
`POST /auth/signup` — body `{email, password, full_name, workspace_name?}` → `201 {user, workspace, access_token}` + refresh cookie. Local-first: first signup creates the workspace with role `owner`; `SIGNUP_MODE=invite_only` afterwards by default.
`POST /auth/login` — `{email, password}` → `200 {access_token, user}`; errors `401 invalid_credentials`, `423 locked` (after 10 failures/15 min).
`POST /auth/refresh` — cookie → new access + rotated refresh (family reuse detection → revoke family, `401 session_revoked`).
`POST /auth/logout` — revokes session.
`GET /auth/me` — `{user, memberships[{workspace, role}]}`.

### Brands
`POST /brands` (admin) — `{name, industry, website, timezone, description?}` → `201 Brand`.
`PUT /brands/{id}/settings` (admin) — full or partial sections `{voice?, policies?, topics?, visual?, platforms?, goals?, audience?, offering?}` validated by section models → `200 BrandSettings`; invalidates BrandContext cache; audit.
`POST /brands/{id}/import-from-website` (admin) — `{url}` → `202 {run_id}`; result: proposed settings for confirmation (`GET /ai/runs/{run_id}` result.deliverables.proposed_settings).

### Social
`GET /social/connect/{platform}?brand_id&flavor` (admin) → `200 {auth_url, state}`; stores `oauth_states` (10 min TTL, PKCE where used).
`GET /social/callback/{platform}?code&state` (public, validates state → user) → exchanges code, lists connectable accounts; if more than one: `200 {selection_token, accounts[]}` then `POST /social/connect/{platform}/select {selection_token, external_id}`; else creates account → redirects to `/w/{ws}/settings/social?connected={id}`. Errors: `400 invalid_state`, `502 platform_error {platform_code, message}`.
`POST /social/accounts/{id}/test` → runs `probe()` → `200 AccountHealth{token_valid, scopes_missing[], capabilities, limits_remaining}`.
`DELETE /social/accounts/{id}` → revokes tokens where the platform supports it, status `disconnected`; refuses (`409`) if live scheduled posts exist unless `?force=true` (cancels them).

### Research
`POST /research/runs` (editor) — `{query, scope:[web,news,rss,competitor_sites], depth, recency_days?, brand_id, competitor_id?, domains_allow?, domains_deny?}` → `202 {run_id, ai_run_id}`.
`GET /research/runs/{id}` → `{status, result{summary, findings[{text, source_ids}], topics, gaps}, sources[{id, title, domain, published_at, relevance, credibility, summary}], cost_usd}`.
`GET /research/sources?q&domain&competitor_id&min_credibility&since` → paginated.

### Competitors
`POST /competitors` (editor) — `{brand_id, name, website?, profiles:[{platform, handle|url}], monitoring_frequency}` → `201 Competitor{profiles[{platform, availability}]}` and enqueues sync.
`POST /competitors/{id}/sync` → `202 {job_id}`.
`GET /competitors/compare?ids=a,b,c&period=90d` → `{columns:[brand, …competitors], rows:[{metric, values[], availability[]}]}`.

### Ideas & content
`POST /ideas/generate` (editor) — `{brand_id, count, pillars?, platforms?, from:{trend_ids?, research_run_id?, insight_ids?, prompt?}}` → `202 {run_id}`.
`POST /content` — `{brand_id, title, content_type?, pillar_id?, campaign_id?, master_format, body?}` → `201 ContentItem`.
`POST /content/{id}/generate` — `{mode: write|rewrite|shorten|expand|change_tone|regenerate, platform?, format?, instructions?, source_ids?, length?}` → `202 {run_id}`; on completion a new version is attached and status becomes `ai_generated`.
`POST /content/{id}/repurpose` — `{targets:[{platform, format, social_account_id?}]}` → `202 {run_id}` → creates variants.
`POST /content/{id}/transition` — `{to: content_status_t, comment?}`; guard matrix: `draft→needs_review` (editor), `needs_review→approved|rejected` (approver), `*→archived` (admin), `approved→draft` (editor, invalidates schedules → `409` if scheduled). Emits `CONTENT_STATUS_CHANGED`.
`POST /content/{id}/request-approval` — creates `approvals(kind=content)` → `201 Approval`; `APPROVAL_REQUESTED`.
`PATCH /content/{id}/variants/{vid}` — `{text?, segments?, hashtags?, platform_metadata?, media_plan?}` → new version; re-validates (`validation` in response).

### Approvals
`POST /approvals/{id}/approve` (approver) — `{comment?}` → `200 Approval`; side effects: content `approved`; for `ai_action` executes the proposed action and resumes the run; for `automation_step` resumes the run. `POST /approvals/{id}/reject` — `{comment}` (required).

### Scheduling & publishing
`POST /scheduling/posts` (editor) — `{content_variant_id, social_account_id, scheduled_at (ISO, tz offset), timezone, priority?}` → validation (`validate_content`), limit checks → `201 ScheduledPost` or `422 {errors:[{code, message, field}]}` or `409 duplicate_live_schedule`. Requires variant status `approved` unless workspace policy allows scheduling drafts (never auto-publishes unapproved: the scheduler re-checks status at dispatch time and pauses with a notification if the variant is no longer approved).
`PATCH /scheduling/posts/{id}` — `{scheduled_at?, timezone?, priority?}` (status `scheduled`/`queued` only, else `409`).
`POST /scheduling/best-times` — `{brand_id, platform, social_account_id, from, to, count}` → `{slots:[{at, score, basis, n}]}`.
`POST /publishing/publish-now` — `{content_variant_id, social_account_id}` → `202 {scheduled_post_id}` (creates a scheduled post at `now()` with priority 10).
`GET /publishing/queue?status=` → scheduled/queued/publishing/failed with attempts and `next_attempt_at`.
`POST /publishing/attempts/{id}/retry` (editor) — only for `failed` posts → `202`.
`DELETE /publishing/published/{id}` (admin) — platform delete → `200 {deleted_at}` or `409 platform_does_not_support_delete` (TikTok).

### Analytics & insights
`GET /analytics/overview?brand_id&from&to&compare=previous` → KPIs with `basis`/`coverage` per metric.
`GET /analytics/breakdown?brand_id&by=pillar|format|platform|campaign|hour&metric=engagement_rate&from&to` → `{groups:[{key, n, value, ci}], coverage}`.
`POST /insights/analyze` — `{brand_id, period}` → `202 {run_id}`.
`PATCH /insights/recommendations/{id}` — `{status: accepted|rejected}` → may enqueue `ideation`.

### AI
`POST /ai/runs` — `{message, brand_id?, conversation_id?, mode: chat|task|tool, agent?, action?, inputs?, budget_usd?}` → `202 {run_id, conversation_id}`. Errors: `402 budget_exceeded`, `409 clarification_required {question}` (when the router needs input synchronously in `tool` mode).
`GET /ai/runs/{id}` → `{status, intent, plan{tasks[{key, label, agent, status, duration_ms, cost_usd, sources_count}]}, result{deliverables, sources[], reasoning_summary, actions[{approval_id, description, status}]}, cost_usd, tokens, error}`.
`GET /ai/runs/{id}/tool-calls` → paginated `{tool_name, side_effect, args_summary, result_summary, status, duration_ms}`.
`POST /ai/runs/{id}/cancel` → `202`. `POST /ai/runs/{id}/resume` → `202` (from `awaiting_approval`/`paused`).
`PUT /ai/settings` (admin) — routing/providers/media/search/safety/budgets (keys are submitted once and stored encrypted; responses return `last4` only).
`GET /ai/usage?from&to&group_by=agent|model|day` → cost dashboard data.

### Automations
`PUT /automations/{id}` (admin) — `{name, nodes[], edges[], settings, autonomous_actions_enabled}` → validation errors as `422 {errors:[{node_key, message}]}`.
`POST /automations/{id}/run` — `{payload?, dry_run?}` → `202 {run_id}`.

### Events (SSE)
`GET /events/stream?workspace_id&topics=runs,publishing,notifications` → `text/event-stream`; events `{id, name, payload}`; supports `Last-Event-ID` replay from a 10-minute Redis buffer. Heartbeat every 15 s.

### Webhooks (inbound)
`POST /webhooks/meta` (signature `X-Hub-Signature-256`), `GET /webhooks/meta` (verification challenge), `POST /webhooks/{platform}` generic. Payloads are stored (`audit_logs` + queue) and processed asynchronously.

## 17.4 Security headers & CSRF
Same-origin proxy means cookies are first-party; state-changing requests require the `X-CSRF-Token` double-submit header (token in a readable cookie) in addition to `SameSite=Lax`. `Content-Security-Policy` strict on the frontend; API returns `Cache-Control: no-store` for authenticated responses.
